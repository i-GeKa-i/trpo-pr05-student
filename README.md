# Каталог товаров

Веб-приложение на PHP для просмотра каталога товаров с фильтрацией по категории и наличию. Учебный проект по дисциплине «Технологии разработки программного обеспечения», практическая работа №5 «PHP ООП. Классы, конструкторы и модели предметной области».

## Возможности

- загрузка товаров и категорий из JSON-файлов и преобразование их в объекты предметной области;
- вывод каталога в виде карточек с названием, категорией, ценой и статусом наличия;
- фильтр по категории и по наличию;
- статистика по выбранному набору: количество найденных товаров и средняя цена;
- обработка ошибочных состояний: пустая выдача, неизвестная категория, некорректные строки данных, недоступный файл данных.

## Требования

- PHP 8.1 или выше
- Git       

Composer и внешние библиотеки не требуются.

## Установка и запуск

```bash
git clone https://github.com/i-GeKa-i/trpo-pr05-student.git
cd trpo-pr05-student
php -S 127.0.0.1:8000 -t public
```

После запуска откройте в браузере <http://127.0.0.1:8000/>. Для остановки сервера нажмите `Ctrl+C`.

## Проверка работоспособности

Автоматические проверки (конструкторы, фильтр, агрегаты, обработка некорректных данных):

```bash
php tests/check.php
```

Успешное выполнение завершается кодом выхода `0`, все строки вывода имеют пометку `[ OK ]`.

Ручной сценарий:

1. Откройте главную страницу: отображаются 12 товаров, средняя цена — 1 192,75 ₽.
2. Выберите категорию «Оборудование»: отображаются 4 товара.
3. Включите «Только в наличии»: товары №5 и №10 скрываются.
4. Откройте `/?category=abc` или `/?category=99`: выводится сообщение «Такой категории нет», каталог показывается целиком, предупреждений PHP нет.
5. Очистите поле `name` у любой записи в `data/products.json`: над каталогом появится сообщение о пропущенной строке, остальные товары отображаются.

## Архитектура

```
products.json ──┐
                ├─► CatalogService ─► Product / Category ─► index.php ─► HTML
categories.json ┘   чтение, фильтр,    данные и поведение,   вывод,
                    агрегаты             валидация            экранирование
```

| Элемент | Ответственность |
|---------|-----------------|
| `Product` | Состояние товара (`id`, `name`, `price`, `categoryId`, `active`) и предметные методы: `isAvailable()`, `belongsTo()`, `priceWithDiscount()`, `formattedPrice()`, `isFree()`. Конструктор не допускает некорректное состояние и выбрасывает `InvalidArgumentException`. |
| `Category` | Идентификатор и название категории. Товар связан с категорией по `categoryId`. |
| `CatalogService` | Чтение JSON, создание объектов, пропуск некорректных строк с сохранением причин (`errors()`), фильтрация (`filter()`), вычисление средней цены (`averagePrice()`). HTML не формирует. |
| `public/index.php` | Единственное место, где формируется HTML: разбор параметров формы, экранирование через `htmlspecialchars`, состояния «пусто» и «ошибка». |

Набор свойств классов соответствует `data/class_requirements.csv`. Поле `active` в `products.json` необязательное: при его отсутствии товар считается доступным.

## Принятые решения

- **Модель отделена от представления.** Модели не содержат HTML; изменение формата цены в `Product::formattedPrice()` не требует правки шаблона.
- **Конструктор гарантирует корректность объекта.** Пустое название, отрицательная цена, неположительные идентификаторы отклоняются при создании.
- **Ошибки данных не прерывают работу.** Некорректная строка пропускается и показывается пользователю; недоступный файл данных отображается как ошибка загрузки.
- **Подключение классов через `require_once`.** Для проекта из трёх классов этого достаточно. При росте проекта ручные подключения становятся неудобны: список разрастается, важен порядок, легко пропустить файл. В этом случае следует перейти на автозагрузку PSR-4 (`spl_autoload_register` или Composer).
