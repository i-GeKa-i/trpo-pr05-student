# Каталог товаров

Небольшое PHP-приложение, которое показывает каталог товаров с фильтром по категории и расчётом средней цены. Данные читаются из JSON-файлов и превращаются в объекты предметной области.

Практическая работа №5 по дисциплине «Технологии разработки программного обеспечения» — «PHP ООП. Классы, конструкторы и модели предметной области».

## Возможности

- карточки товаров с категорией, ценой и статусом наличия;
- фильтр по категории и по наличию;
- количество найденных товаров и средняя цена по выборке;
- понятные сообщения для пустого результата, неверной категории и повреждённых данных.

## Требования

- PHP 8.1 или новее (проверено на 8.4)
- Git

Composer и другие зависимости не нужны.

## Запуск

```bash
git clone https://github.com/i-GeKa-i/trpo-pr05-student.git
cd trpo-pr05-student
php -S 127.0.0.1:8000 -t public
```

Откройте в браузере <http://127.0.0.1:8000/>. Остановить сервер — `Ctrl+C`.

## Проверка

```bash
php tests/check.php
```

Скрипт выводит результат каждой проверки; код выхода `0` означает, что все проверки пройдены.

## Как пользоваться

1. На главной странице отображаются все товары.
2. Выберите категорию в списке и/или отметьте «Только в наличии», затем нажмите «Применить».
3. Кнопка «Сбросить» возвращает полный каталог.

## Архитектура

```
products.json ─┐
categories.json┴─► CatalogService ──► Product / Category ──► index.php ──► HTML
```

| Элемент | Ответственность |
| --- | --- |
| `Product` | Состояние товара (`id`, `name`, `price`, `categoryId`, `active`) и его поведение: `isAvailable()`, `belongsTo()`, `priceWithDiscount()`, `formattedPrice()`, `isFree()`. Проверяет данные в конструкторе и выбрасывает `InvalidArgumentException` при ошибке. |
| `Category` | Идентификатор и название категории. Товар связан с ней через `categoryId`. |
| `CatalogService` | Читает JSON, создаёт объекты, пропускает некорректные строки (причины доступны через `errors()`), фильтрует каталог и считает среднюю цену. |
| `index.php` | Только представление: проверяет параметры фильтра, экранирует значения (`htmlspecialchars`) и выводит карточки. |

Модели не содержат HTML, а обработка фильтра не смешана с классом `Product`.

## Формат данных

- `data/products.json` — массив объектов `id`, `name`, `price`, `category_id`; необязательное поле `active` (по умолчанию `true`).
- `data/categories.json` — массив объектов `id`, `name`.

Строка с пустым названием, отрицательной ценой или несуществующей категорией не попадает в каталог; приложение сообщает об этом над списком товаров.

## Заметки по реализации

- **Предметные методы.** Логика наличия, скидки, формата цены и принадлежности категории находится в `Product`, а не в HTML. Способ хранения цены можно изменить, не трогая шаблон.
- **Подключение классов.** Используется `require_once`. С ростом проекта ручные подключения становятся неудобны: их нужно держать в правильном порядке и не забывать. В таком случае применяют автозагрузку PSR-4 (`spl_autoload_register` или Composer).
